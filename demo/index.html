knave-grid

A Swiss grid for static sites, generated from one Knave spec. Every rule, color and box on this page sits on the grid that the spec below describes.

You can also press g, or open this page with ?grid. The pink lines are baselines, and the blue bands are columns.

The type area

Every measure here is in squares: one square is one leading, 27px, in both directions, which is exactly 3ch of Iosevka. The type area follows the width of the screen, and each breakpoint sets its own width, columns, gutter and margins. The check makes sure each type area fits its columns and its breakpoint. Head and foot margins count squares from the page edge to the nearest baseline, so the page starts and ends on a baseline.

The measure

The measure is the length of a line of text. Each type area sets it as a number of its columns, so this paragraph, limited to var(--measure), ends on a column edge. The demo leaves the number out, so the library picks the widest span within 66ch, the usual target for comfortable reading: two columns on wide screens, 19 squares or 57 characters of Iosevka. The library warns when a span holds fewer than 45 or more than 75 characters, and refuses a span wider than the type area. Lines that run much longer than this make the eye lose its place on the way back to the start of the next line.

Baselines

The leading is 27px, the distance from one baseline to the next. The demo task read Iosevka's metrics from its WOFF2 file and placed the baseline {{baseline-offset}} below the top of each line. Turn on the overlay: every line of text on this page rests on a pink line.

  • Headings, lists, code and tables all use the body leading, so they stay on the grid.
  • Spacing between blocks is a whole number of leadings, written as calc(n * var(--leading)).
  • Boxes draw their edges with shadows, which take no space, so a border never pushes the next line off.

Type styles

A type style says how many grid lines tall it is, and its type grows with it. The library shifts each style so its baseline lands on the last body baseline in its block, or on the line the spec names, without changing the block's height, so the text after it stays on the grid. Turn on the overlay to see each one sit on a pink line.

Picture fields

Müller-Brockmann's rule for pictures (Grid Systems in Graphic Design, p. 65): the picture's top edge lines up with the tops of the capitals in the first line of its field, and its bottom edge with the descenders of the last line. A .field element follows it: set --field-lines to the number of lines it spans. Its box stays a whole number of lines tall, so the text after it stays on the grid. Turn on the guides to see each line's cap line and descender line in amber, with or without the grid.
