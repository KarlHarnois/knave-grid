knave-grid

A Swiss grid for static sites, generated from one Knave spec. Every rule, color and box on this page sits on the grid that the spec below describes.

Press g to show the grid overlay, or open this page with ?grid. The pink lines are baselines, and the blue bands are columns.

The spec

The page's grid is plain Knave data. The demo task reads the font metrics from the font file, checks the spec, and writes the CSS. This is the spec it built, as Knave prints it:

{{spec}}

The type area

The type area is 117ch wide, with a 3ch gutter. Four columns fit because 4 divides 117 + 3 = 120, so each column is {{column-width}} wide.

A column is a vertical division of the type area. This one is the first of four.

A gutter is the space between two columns. The overlay leaves it clear.

The .grid rule lays these cells out with repeat(var(--columns), var(--column)).

Each cell's text sits on the same baselines as the text around it.

The measure

The measure is the length of a line of text. This paragraph is limited to var(--measure), which the spec sets to 66ch, the usual target for comfortable reading. The library warns when a measure falls outside 45ch to 75ch, and refuses a measure wider than the type area, because no text could be set at it. Lines that run much longer than this make the eye lose its place on the way back to the start of the next line.

Baselines

The leading is 27px, the distance from one baseline to the next. The demo task read Iosevka's metrics from its WOFF2 file and placed the baseline {{baseline-offset}} below the top of each line. Turn on the overlay: every line of text on this page rests on a pink line.

  • Headings, lists, code and tables all use the body leading, so they stay on the grid.
  • Spacing between blocks is a whole number of leadings, written as calc(n * var(--leading)).
  • Boxes draw their edges with shadows, which take no space, so a border never pushes the next line off.
